## O que um bloco (#30 a #42) cria e qual comando roda

As Issues de bloco rodam em paralelo. Para cada serviço com preço da Issue (slug = tipo do bloco sem `aws.`; no nome do módulo, `-` vira `_` e `lambda` é `lambda_`):

1. **Edita** `pricing/app/services/<slug com _>.py` (já existe, provisório): `queries(region)`, `build(region, products)` e `expected_skus`.
2. **Cria** `pricing/tests/test_service_<slug com _>.py`, com a resposta do `GetProducts` simulada.
3. **Preenche** `web/public/prices/us-east-1/<slug>.json` e `web/public/prices/sa-east-1/<slug>.json` (já existem, com `prices: []`), no formato de `price-catalog.md`.
4. **Roda** `cd pricing && uv run python -m app seed` e versiona o `web/public/prices/manifest.json` que o comando regrava.
5. **Não toca** em `pricing/app/services/__init__.py`, `pricing/tests/test_services.py`, no `manifest.json` à mão nem em arquivo de outro serviço. No `web/`, o bloco mexe só no arquivo do próprio bloco em `web/src/features/pricing/model/blocks/`.

Por que não há conflito entre blocos:

- **Registro.** Os 17 módulos e a lista `SERVICES` já existem. O teste do registro (`test_services.py`) vale para serviço provisório e para serviço implementado.
- **Manifest.** O `manifest.json` é saída de comando. Cada entrada ocupa 4 linhas (`{`, `path`, `sha256`, `}`), as 34 entradas já existem e a data do manifest `seed` é a constante `SEED_GENERATED_AT`. Um bloco muda só as linhas de `sha256` dos seus arquivos, e o git junta dois PRs que mudam linhas diferentes. Conferido com git de verdade: quatro branches paralelas (alb, cloudfront, cloudtrail e waf, as três primeiras vizinhas no arquivo) fizeram merge sem conflito e o manifest resultante saiu igual, byte a byte, ao de rodar `seed` depois do merge.
- **Conferência.** `pricing/tests/test_seed_catalog.py` falha no `validate` se o manifest versionado não bater com os arquivos, e `web/src/features/pricing/api/generatorContract.test.ts` passa o catálogo versionado pelo carregador real (zod e `sha256`). Quem esquecer de rodar `seed` vê o CI vermelho no próprio PR.

Regras do conteúdo:

- `queries(region)` devolve as consultas (`Query(service_code, filters)`), com `region_filter(region)` mais os filtros do serviço. Os filtros se combinam por AND; famílias diferentes pedem mais de uma `Query`. `ServiceSpec.service_code` é o ServiceCode principal; cada `Query` leva o seu (NAT Gateway usa `AmazonEC2`).
- `build(region, products)` escolhe os produtos pelo `family` e pelos `attributes` e monta os `Price` com SKU, descrição e unidade escritos por nós, usando `tiers(product.dimensions)`. Os SKUs do arquivo semente são os mesmos que o `build` produz.
- A franquia pode vir da Price List como uma faixa de preço `0` no começo. `tiers` a devolve como faixa normal; o `build` decide se a converte em `FreeTier`. No catálogo, a franquia vai em `freeTier`.
- O motor aplica franquia e faixas por conta e trata `pool` como nome global do catálogo. O nome do `pool` começa com o slug do serviço (`lambda-requests`), e todos os SKUs de um pool declaram a mesma `quantity`.
- Valores são string decimal de até 12 casas, sem arredondar. Limites: 200 preços por arquivo, 16 faixas por preço, descrição de até 200 caracteres, unidade de até 40.
- CloudFront e Route 53 são globais na Price List: `region_filter` não serve para eles, e as Issues deles (#31, #38) definem outro filtro. O arquivo continua existindo nas duas regiões.
- Quando o serviço ganha consulta, `python -m app` (com credencial AWS, só no workflow da #29) passa a gerar o arquivo dele. A partir daí valem as checagens: nenhum preço, SKU esperado ausente, preço negativo, 500 KB, mais da metade dos SKUs sumiu ou preço positivo virou zero bloqueiam; variação maior que 30% só é relatada.
- A #41 (blocos de custo zero) não tem arquivo de preço. Se a #42 (arestas) criar um serviço novo para transferência de dados, ela acrescenta o módulo, uma linha em `services/__init__.py`, uma linha na tabela de `test_services.py` (e troca o 17) e os dois arquivos semente; é a única Issue que faz isso. A inserção de entradas novas no manifest também fez merge limpo no teste com git.
