## Decisões

- **Rotas por map, com o route key exato como chave.** O mesmo map gera as rotas e os `route_settings`, então o limite por rota não tem como apontar para rota inexistente (a AWS aceita a chave errada e ignora).
- **O destino da rota sai do caminho, dentro do módulo.** `/estimates` e `/quota` (e o que houver abaixo) vão para o `llm-proxy`; o resto, para a `api`. Quem chama o módulo não escolhe.
- **Só métodos explícitos.** `$default`, `ANY`, `OPTIONS` e `{proxy+}` são rejeitados na validação: com eles o preflight de CORS exigiria uma rota sem authorizer. Com método explícito, o API Gateway responde o preflight sozinho.
- **Formato do log de acesso fixo no módulo**, só com variáveis `$context`. Não é variável para que um ambiente não possa incluir cabeçalho.
- Nenhum pattern introduzido.

## Decisões tomadas sem humano

- **`default_throttle` obrigatório e sem default.** O valor é configuração de custo do autor (runbook de guardrails, passo 2). O README só cita os valores sugeridos pelo runbook.
- **`log_retention_days` com default 7**, o valor do ADR; aceita 1, 3, 5, 7, 14 ou 30.
- **Log de acesso guarda o claim `sub`** (pseudônimo, já chave no DynamoDB) por 7 dias, para atribuir abuso. Não guarda IP, user-agent, e-mail nem cabeçalho.
- **Log group sem CMK do KMS** (custo fixo, vetado pelo ADR) e sem `prevent_destroy` (log descartável). O trivy lista AVD-AWS-0017 em severidade baixa.
- **Nome do log group com prefixo `/aws/vendedlogs/`**, recomendação da AWS para a resource policy do CloudWatch Logs não crescer.
- **`jwt_issuer` aceita só User Pool em `us-east-1`**, a região única do ADR.
- **CORS:** cabeçalhos `authorization` e `content-type`, sem credenciais, `max_age` de 600 s.
- **Timeout das integrações em 30 s** (teto da HTTP API); o limite real é o de cada função.
- **Fatiamento** em #131 e #132, como descrito acima.
- **Handoff em `docs/handoff/131.md`**, não em `19.md`: o corpo da #132 foi ajustado para apontar para cá.
