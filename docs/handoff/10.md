## Decisões tomadas sem humano

| Decisão | Alternativa descartada | Motivo |
| --- | --- | --- |
| Fatiar em #200 (dados) e #201 (HTTP) | Uma parte só | 1.280 linhas > 800. O corte separa contratos de dados da superfície HTTP; cada fatia fica verde sozinha |
| Mapeamento `doc_too_large` → 413 em `app/errors.py` vai na #201 | Deixar na #200 | Só as rotas de designs o usam; tirar daqui mantém a #200 abaixo de 800 |
| Tamanho de string em pontos de código (`max_length` do Pydantic) | Unidades UTF-16 | O zod 4.6.7 instalado conta pontos de código (`web/node_modules/zod/v4/core/checks.js:273`, `util.codePointLength`): 80 emojis cabem num rótulo de 80 |
| Base `ContractModel` com `strict=True` e `extra="ignore"` | Modo lax; `extra="forbid"` | O zod não converte `"1"` em `1`; e a leitura tolerante do web descarta chave desconhecida (rollback entre builds) |
| `schemaVersion: true` recusado por validador | `Literal[1]` puro | O `Literal[1]` do Pydantic aceita `True` mesmo em strict |
| `"__proto__"` descartado dos records antes de validar e contar chaves | Recusar | O zod 4 descarta; o web aceita esse arquivo |
| Os 7 nomes de `Object.prototype` que casam a regex de chave são recusados | Só a regex | Equivale ao `refine` do zod (`Object.hasOwn(Object.prototype, key)`) |
| Números passam por float64; float integral abaixo de 1e21 vira `int` | `int \| float` puro | `doc_size_bytes` fica igual ao `JSON.stringify` do web (`1e12` → `1000000000000`) |
| `estimatedAt: null` recusado; ausência aceita | `str \| None` | O `.optional()` do zod recusa `null` |
| Regex de `estimatedAt` portado do `z.iso.datetime()` do zod 4.6.7, com `[0-9]` | `datetime` do Pydantic | Mesmo veredito (só `Z`, segundos obrigatórios, 29/02 só em ano bissexto); `datetime` em strict recusa string |
| Substituto UTF-16 solto recusado (422) | Aceitar como o zod | Não é serializável em UTF-8: `doc_size_bytes` daria 500 |
| `contracts/` procurado em `/var/task/contracts` (zip) e depois na raiz do repo | Variável `CONTRACTS_DIR`; cópia em `api/` | Sem configuração nova de infra e sem segunda cópia do JSON |
| `default: null` em atributo do `blocks.json` recusado | Aceitar como ausente | Mesmo veredito do zod |
| Exemplos lidos com `node:fs` + `JSON.parse` no vitest | `import.meta.glob` / import de JSON | O plugin de JSON pode transformar `"__proto__"` em literal de objeto |
| `uv` ausente na máquina: suíte da `api/` rodada num venv descartável com as versões exatas do `uv.lock` | Parar | Falha de ambiente; o CI roda com `uv sync --locked` |

## Divergências conhecidas zod × Pydantic

- Substituto UTF-16 solto: o zod aceita, a API recusa.
- Números entre 1e-6 e 1e-5: o JS escreve `0.000001` e o Pydantic `1e-6`; o `sizeBytes` calculado na API fica alguns bytes menor.
- `NaN`/`Infinity` no JSON: o `JSON.parse` recusa o arquivo, o `json.loads` aceita e o modelo recusa depois. Os dois lados dão inválido.
- `loc` de erro em atributo traz nomes de ramo da união do Pydantic (`constrained-str` etc.). O veredito não muda.
