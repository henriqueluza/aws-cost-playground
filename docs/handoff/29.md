- `infra/tools/tests/test_prices_pr_script.py`: os cenários rodam contra um `origin` bare descartável, num clone raso por `file://`, com um `gh` falso.

O que o script faz em cada caso:

| Situação | Resultado |
| --- | --- |
| Igual a `main` (sem contar o manifest), com PR aberto | Fecha o PR com comentário e mantém a branch |
| Igual a `main`, sem PR | `sem mudança` |
| Igual à ponta da branch, com PR aberto | `sem mudança`, sem commit |
| Igual à ponta da branch, sem PR | Cria o PR, sem commit |
| Diferente | Commit, push fast-forward, e edita ou cria o PR |

## Pendências humanas (entram no PR da #222)

- Fazer o `git mv .github/workflows-pending/prices.yml .github/workflows/prices.yml`.
- Criar a variável `AWS_PRICES_ROLE_ARN` quando o papel `prices` existir (#125).
- Ligar "Allow GitHub Actions to create and approve pull requests". Hoje está `false`, e sem isso o `gh pr create` com `GITHUB_TOKEN` falha com 403. Ligar essa opção também deixa um workflow aprovar PR: é decisão de segurança do autor. A alternativa é usar um GitHub App, que exige segredo.
- O PR aberto pelo `GITHUB_TOKEN` não dispara os workflows de `pull_request`. Para rodar o CI, o autor fecha e reabre o PR. O rodapé do corpo do PR já avisa isso.
- Opcional: ligar "Automatically delete head branches". Com a branch `prices/catalogo` mantida depois de um squash merge, o PR seguinte lista os commits antigos (a árvore continua certa; é só ruído no histórico).
