# Handoff — Issue #57: renomear, duplicar, apagar e conflito de versão

## Estado
Completo; todos os critérios de aceite têm teste.

## O que existe
- `hooks/useDesigns.ts`: `useRenameDesign` (`update` só com `name` e a versão lida; se o design aberto é o renomeado, a store guarda o novo nome/versão sem tocar no documento), `useDuplicateDesign`, `useDeleteDesign` (se o apagado está aberto, solta o vínculo: o próximo salvar cria outro). Todos invalidam a lista.
- `ui/DesignsPage.tsx`: ações por linha (Renomear, Duplicar, Apagar). Apagar pede confirmação em `Dialog`. Duplicar no limite de 50 mostra a mensagem de `design-limit` (antes de pedir nome, e também se a API recusar).
- `ui/SaveControls.tsx`: em `version-conflict` o diálogo oferece "Recarregar versão salva" (descarta a edição local) e "Salvar como cópia" (`useSaveDesign` com `asCopy`: cria design novo, nunca grava sobre o salvo). Nada é sobrescrito em silêncio.
- `model/designMessages.ts`: mensagem de conflito atualizada; `copyName` (sufixo " (cópia)" cabendo nos 80 caracteres).

## Decisões tomadas sem humano
- Nome padrão da cópia: "<nome> (cópia)". Reversível.
- Apagar desvincula o design aberto em vez de limpar o editor: o trabalho na tela não se perde.
- Rename com versão velha (outra aba) mostra a mensagem de conflito na lista; a lista é recarregada.

## Próximo passo / pendências
Nenhum. Testes: `npx vitest run src/features/designs`.
