# Handoff — Issue #121: registros de alias do módulo de DNS (parte 2 de #15)

## Estado

PR na branch `issue-121-dns-alias`. Fecha a #121 e a #15. O módulo `infra/modules/dns` está completo.

O que entrou em `infra/modules/dns`:

- `variables.tf`: `site_alias`, `api_alias` e `auth_alias`, cada uma `object({ name = string, zone_id = string })` com `default = null`.
- `main.tf`: `aws_route53_record.site`, `.api` e `.auth`, com `count` 0 ou 1. Cada um é um registro `A` alias com `evaluate_target_health = false`, na zona lida, com o nome de `local.domain_names`.
- `outputs.tf`: `auth_domain`, com `depends_on = [aws_route53_record.site]`.
- `tests/dns.tftest.hcl`: três runs novos (os três alias com alvo, só um alvo informado e o consumidor com Cognito) e o assert "sem alvo, sem registro" no run do apex.
- `tests/consumer/main.tf`: consumidor mínimo, só de teste. O domínio do Cognito lê `auth_domain` e `certificate_arns["auth"]` e devolve o alvo em `auth_alias`. O plan dele só passa se não houver ciclo.
- `README.md`: variáveis, output, exemplo e regras de uso dos alias.

Verificado na máquina (Terraform 1.16.0):

- `terraform fmt -check`, `validate` e `terraform test` passaram (6 de 6).
- Mutação: trocar os três blocos por um único `for_each` sobre um map faz o run `consumidor_com_cognito_sem_ciclo` falhar com `Error: Cycle`.
- `terraform graph -type=plan` mostra a aresta `output.auth_domain -> aws_route53_record.site`.

## Decisões tomadas sem humano

1. **Código trazido de `wip/issue-15-dns-alias`, testes e README não.** Os `.tf` vieram iguais. A branch de referência reescrevia os testes e o README da parte 1 de forma mais curta. Mantive os de `main` e só acrescentei os alias, para não perder asserts já revisados.
2. **Fixture `tests/consumer/` para o critério "nenhum ciclo".** Sem ela, o critério dependeria só da disciplina de quem edita o módulo. Com ela, um `for_each` único quebra o `terraform test`. A fixture tem bloco `terraform` com as mesmas versões dos módulos, para o tflint `recommended` não reclamar.
3. **Sem `prevent_destroy` nos alias.** Registro de DNS não guarda dado nem identidade, que é o critério do ADR. Na troca de alvo o provider faz update in-place, sem replace.
4. **Sem validação extra nos objetos de alias.** O tipo já exige `name` e `zone_id`, e os valores vêm de recursos do mesmo estado. Um valor inválido falha no provider, no plan.
5. **Orçamento.** O primeiro corte tinha 161 linhas. Tirei um assert redundante (o plan do consumidor já é o teste) e juntei o assert de `auth_domain` ao dos alias. Ficou em 150 linhas (69 de código e 81 de teste).
